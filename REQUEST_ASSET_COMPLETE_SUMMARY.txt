STEP 1: USER CREATES REQUEST

User logs in → Asset Management → Request Asset → Create Request tab
├─ Fills form with:
│  ├─ Department
│  ├─ Priority level (Low, Medium, High, Urgent)
│  ├─ Items (add multiple):

├─ System generates Request ID (AR-001 format)
├─ Request stored in database
└─ Status set to "Pending Approval"

STEP 2: ADMIN REVIEWS REQUEST
──────────────────────────────────────────────────────────────────────────────
Admin goes to Manage Asset Requests page
├─ Sees all pending requests from all users
├─ Clicks request ID to see full details
├─ Views:
│  ├─ Request information
│  ├─ All requested items with details
│  └─ Requester information
├─ Decision:
│  ├─→ APPROVE: With optional approval notes
│  └─→ REJECT: With mandatory rejection reason

──────────────────────────────────────────────────────────────────────────────

├─ Status changes to "Approved"
├─ Approved by field updated
├─ Approval notes saved
├─ Audit log entry created
└─ (Future: Can auto-create procurement request)

If REJECTED:
├─ Status changes to "Rejected"
├─ Rejection reason stored
├─ Rejected by field updated
├─ Audit log entry created

──────────────────────────────────────────────────────────────────────────────
User logs back in → Asset Management → Request Asset
├─ My Requests tab shows:
│  ├─ Request with new status (Approved/Rejected)
│  ├─ Status badge color-coded
│  ├─ If rejected: can see rejection reason
│  └─ If approved: can track next steps

STEP 5: AUDIT TRAIL CREATED
──────────────────────────────────────────────────────────────────────────────
Complete history recorded:
├─ Action: CREATED
│  ├─ When: Request creation timestamp
│  ├─ Who: User who created it

│  ├─ When: Approval/rejection timestamp
│  ├─ Who: Admin who approved/rejected
│  └─ What: Approval notes or rejection reason

═══════════════════════════════════════════════════════════════════════════════
                          TROUBLESHOOTING GUIDE
═══════════════════════════════════════════════════════════════════════════════

ISSUE: Page shows "Unauthorized" error
SOLUTION:
├─ Make sure you're logged in
├─ Check $_SESSION['id'] is set
└─ Clear browser cookies and login again

ISSUE: Form doesn't submit / No response
SOLUTION:
├─ Check browser console (F12) for JavaScript errors
├─ Verify API files exist (api/asset_requests.php)
├─ Check database connection (verify_asset_module.php)
└─ Look at XAMPP error logs for PHP errors

ISSUE: Admin page shows no requests
SOLUTION:
├─ Verify requests exist in database
├─ Check status filter (default is "Pending Approval")
├─ Try creating a test request first
├─ Check database connection

ISSUE: Sidebar menu item doesn't appear
SOLUTION:
├─ Clear browser cache (Ctrl+Shift+Delete)
├─ Hard refresh (Ctrl+Shift+R)
├─ Verify layout/adminLayout.php modification
└─ Restart browser

ISSUE: Notifications don't appear
SOLUTION:
├─ Check browser notifications settings
├─ Verify Toastify.js is loaded (check Resources tab)
├─ Check browser console for JavaScript errors
└─ Verify showToast() function is called

ISSUE: Database connection error
SOLUTION:
├─ Check api/db.php configuration
├─ Verify MariaDB is running
├─ Check username and password in db.php
├─ Verify database name is correct
└─ Run verify_asset_module.php for diagnostics
